# Capital One OA track + timed mock — design

Date: 2026-08-16. Status: approved.

## Goal

Prepare for Capital One's online assessment: CodeSignal's General Coding Assessment —
70 minutes, 4 questions, proctored. Question shape (research-verified, 2025–2026):
Q1/Q2 easy array/string warm-ups, Q3 implementation-heavy 2-D matrix/simulation,
Q4 algorithmic medium (hashmap, stack, greedy, parsing). Dynamic programming is
generally absent.

Two deliverables: a new `capital-one` exercise category (20 Python problems in
slot pools), and a timed 70-minute mock mode that draws a 4-question sitting from
those pools.

## Content: the `capital-one` category

- Category id `capital-one`, display name "Capital One", `KindCoding`, Python only.
- 20 original problems in GCA style, banking-flavored where natural. No copied
  LeetCode text.
- Slot encoded in the problem id prefix — no schema changes:
  - `c1-warmup-01..08-python` — easy; array/string manipulation (GCA Q1/Q2).
  - `c1-grid-01..06-python` — medium; implementation-heavy 2-D matrix/simulation
    (GCA Q3): grid traversal with fiddly rules, cellular-automaton-ish steps,
    spiral/rotation/region bookkeeping.
  - `c1-algo-01..06-python` — medium; hashmap / monotonic stack / greedy /
    string parsing (GCA Q4).
- Standard exercise layout per repo convention: `exercises/<id>/exercise.json`,
  `repo/problem.md`, `repo/solution.py` (starter, must fail hidden tests),
  `.reference/solution.py` (must pass), `tests/<id>/test_*.py`.
- `time_limit_min` for standalone practice: warmup 10, grid 25, algo 20.
- Difficulty field: warmups `easy`, grid and algo `medium`.

## Mock session (approach A: sequential containers, shared clock)

- New "Mock" entry in the main menu (`menuLabels`, `internal/tui/app.go`).
- Start screen: format explainer, previous-sittings history line, confirm to start.
- Draw: slots [warmup, warmup, grid, algo]. Within each slot pool prefer unsolved
  problems, then least-recently-attempted; no repeats within a sitting.
- Clock: the Go host records a wall-clock deadline (start + 70 min). Each question's
  container is launched with the remaining whole minutes as `PRACTICE_TIME_LIMIT_MIN`,
  so `docker/clock.sh` and the tutor clock work unchanged. Between-question time
  counts against the 70 minutes. Laptop sleep during a mock burns the clock —
  intentional (mock realism); single-exercise practice keeps its uptime-based clock.
- Forward-only navigation: pass or give up advances; resubmits allowed as in normal
  practice; no returning to earlier questions (known divergence from CodeSignal's
  free navigation — accepted trade-off of approach A).
- Deadline expiry: the current question may finish (clock shows TIME UP as today);
  no further questions launch; unattempted slots record as skipped.

## Results & persistence

- End-of-sitting summary screen: per-slot outcome (solved / attempted / skipped),
  time per question, total solved /4, total elapsed. No synthetic 200–600 score —
  CodeSignal's scale cannot be calibrated honestly from outside; report facts only.
- Each question logs a normal `tracker.Attempt` — review/due/stats machinery
  untouched.
- New `mocks.jsonl` alongside tracker data: one row per sitting
  `{started_at, problem_ids, outcomes, minutes_total, minutes_per_slot, completed}`.
  Feeds the start-screen history line ("N sittings, best X/4").

## Edge cases

- Pool exhaustion (everything solved): fall back to least-recently-attempted;
  the draw never blocks.
- Quit mid-mock (leave keybind / ctrl-c): sitting recorded with `completed: false`
  and whatever slots finished; no resume — a new mock is a new draw.
- Mocks ignore `allowedDifficulties` gating (explicit opt-in; sittings must include
  mediums even on a fresh profile). Daily/picker gates unchanged.
- Tracker or mock-log write failures surface as errors — no silent swallowing.

## Testing

- TDD. Unit tests: draw logic (slot mapping, prefer-unsolved, no repeats,
